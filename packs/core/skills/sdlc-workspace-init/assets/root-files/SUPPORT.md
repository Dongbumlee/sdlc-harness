# Support

## Getting help

- **Questions and usage help** — open a GitHub Discussion (or, where
  Discussions are not enabled, an issue labelled `question`). Search
  existing threads first; an answered thread helps the next person too.
- **Bug reports** — open an issue with the version, the exact steps to
  reproduce, what you expected, and what happened. Logs and a minimal
  example shorten the path to a fix.
- **Feature requests** — open an issue describing the problem you are
  trying to solve, not only the solution you have in mind.
- **Security problems** — never a public issue. See `SECURITY.md` for
  the private reporting path.

## Response expectations

Maintainers triage new issues within 3 business days. Support is
best-effort: there is no SLA, and older releases receive no fixes —
see `SECURITY.md` for the supported-versions policy.

## Before you ask

Read the README and the project documentation first, and make sure you
are on the latest release before reporting a problem.
