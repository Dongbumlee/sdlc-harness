# Contributing

## Before you start

- Search existing issues and pull requests first — the change may
  already be proposed or in progress.
- For anything larger than a small fix, open an issue and agree the
  approach with the maintainers before writing code.

## Making a change

1. Branch from `main`; keep the change to one purpose.
2. Follow the project's conventions (the instruction files under
   `.github/instructions/`, where present) and keep the change
   complete — no half-migrated states.
3. Add or update tests for behaviour you change, and run the full
   local suite before pushing.
4. Update the documentation in the same change when behaviour,
   configuration, or interfaces move.

## Pull requests

Open the PR against `main` and fill in the pull request template —
the SDLC phases the change covers, how it was tested, and the design
reference where one exists. A PR is ready to merge when CI is green
and the template is filled in, not before.
