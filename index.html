01 / SYSTEM

One front door.
A full engineering bench.

Talk to one Harness agent. It identifies the SDLC phase, verifies prerequisites, delegates to the right specialist, and keeps quality gates in the path to release.

02 / INTAKE

The design conversation comes first.

Before any work opens, Harness holds a short structured conversation and writes down what was agreed. No confirmed brief, no build.

Most agent failures are framing failures: the wrong problem, built well. The conversation exists to catch that before anything is built, when changing direction is still cheap.

Every job is also sized — Small, Medium, or Large — which sets its budget and how the work is organized.

  • Five points, agreed with you and written down
  • Later changes are judged against the brief — small ones fit inside it, big ones reopen it
  • Every job is tracked in one place from the start
  • Unattended jobs skip the conversation — and record that they did
Sized before work starts — Small ≤ 4 hours · Medium ≤ 2 days · Large ≤ 5 days — each with a budget agreed up front.

03 / WORKFLOW

Ten phases.
No silent shortcuts.

Every request enters a traceable path from workspace setup to publish. The Harness chooses the route; engineers remain the decision-makers.

00HARNESS

Workspace & intake

Set up the workspace, hold the design conversation, and size the job before anything is built.

01ANALYST

Requirement analysis

Discover goals, constraints, and non-functional requirements; the user approves the summary before it becomes a spec.

02ANALYST

Design

Shape the architecture and record decisions as ADRs — files that must exist before the phase can close.

03SCAFFOLDER

Repo & CI/CD

Instantiate a bundled template, complete the manifest, and validate that the scaffold builds and tests clean.

04IMPLEMENTER

Implementation

Write production code and tests against explicit acceptance criteria.

05DOCUMENTER

Documentation

Update ADRs and API documentation against the code that actually shipped.

06QA COORDINATOR

QA activities

Run nine independent review domains in parallel and synthesize prioritized findings.

07RAI REVIEWER

Responsible AI

Assess safety, transparency, grounding, and model-facing behavior. A block here stops the release.

08RELEASE MANAGER

Release prep

Verify exit criteria, prepare the changelog, and assemble a reviewable pull request. The release decision stays human.

09RELEASE MANAGER

Publish

Move the approved change across the final release boundary.

ENTRY

Enter at any phase

A request can start at the phase it needs — prerequisites are checked before work proceeds. Small jobs combine analysis and design into one step; larger jobs keep them separate.

05 / ADVERSARIAL QA

A review engine that is allowed to say no.

Independent contexts, anti-leniency instructions, numeric scoring, and hard failure rules turn review from a polite ritual into an evidence gate.

ticks mark the pass gate on a 0–10 scale — thresholds, not scores

Find. Fix. Re-review the part that failed.

Nine review domains work in parallel without seeing one another’s findings. A miss does not restart everything: targeted fixes go back first, and the full panel reconvenes only when that is not enough.

01

Independent contexts

Reviewers do not inherit the generator’s rationale or anchor on one another’s verdicts.

02

Hard-fail thresholds

Security below 8, any domain below 7, composite below 7, or a single Critical finding stops the release.

03

Escalation with limits

Failed domains are re-reviewed alone first. If that is not enough — or three or more are down — the full panel reconvenes. Rounds are capped by the size of the job.

weighted composite = (security × 1.5 + sum of other reviewers) / 9.5
06 / PIT-STOP GUARDS

The run watches itself, too.

Every failure lands in an append-only ledger. When the counts cross a line, Harness stops delegating, reviews its own run, and changes course — or hands the evidence to you.

01

Same failure, third time

The same tool failure shows up a third time in the ledger.

02

Same rework, twice

Work comes back for the same reason a second time.

03

Claim vs. disk

A worker’s report contradicts the artifacts actually on disk.

04

Thirty silent minutes

Roughly half an hour passes with no change to any artifact.

05

Same order, third time

The same delegation would be issued unchanged a third time. It is not issued.

At most three reviews per run. At the cap, the run stops and the trigger and its evidence go to the user — the harness never loops quietly.

08 / QUICK START

Install once.
Bring the whole system.

Use the Agent Plugin in VS Code or GitHub Copilot CLI. Then open a project and ask Harness to initialize the workspace.

  • VS Code + GitHub Copilot Chat
  • Python 3.12+ and uv
  • Git 2.40+ and Docker
  • Cloud CLI tooling when using a cloud pack (AWS/GCP/Azure)
# Register the marketplace once $ copilot plugin marketplace add Dongbumlee/sdlc-harness # Install the plugin $ copilot plugin install sdlc-harness@sdlc-harness
# Open your project, then start Harness /agent harness initialize workspace # Harness deploys MCP config, quality instructions, # and prompt files, then opens the design conversation.

VS Code requires chat.agent.defaultApproval: autopilot and github.copilot.chat.virtualTools.threshold: 0. Start MCP servers, then open a new Chat session so tools are registered.
